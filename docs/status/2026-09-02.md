# Status report, 2026-09-02 (day 1)

Written for the maintainer, who follows the project on GitHub. Everything below is on `main`.

## Honest one-line summary

The engine is not a playable game yet: it boots into the original main menu (pictures, fonts and strings from
the player's files), Play! loads the first mission (`H01_Lin_VL`, Lincoln) behind its three briefing pages
with the camera on Robin, you can select Robin and walk him around obstacles with pathfinding, characters
animate with the real sprites (every NPC with the sprite the profile table assigns), guards walk their rail
programs, Escape opens the pause menu (continue, restart, quit with confirmation), the HUD frame is drawn at
the measured positions, credits play, music plays; the main menu and the briefing scene match the original's
captures (SSIM 0.9995 / 0.986 with the profile text and the parchment masked), and the whole flow also works
in the real window with OS-level mouse input. But there are no objectives, dialogues, combat, view cones,
options, profiles or saves. The first script VM runs the missions' scripts (ADR-0008): the first mission's
briefing pages, objectives, messages and the archery-training loop come from its script now; 56 natives are
implemented, 33 are recorded stubs, unknown ones trap. The format work that the whole port depends on is
largely done (see below), and the test harness plays the engine autonomously.

## What does not work yet

- Script VM: first version. All 39 scripts translate; 26 trap in `Initialize` on a native without a documented row (strict mode). Sequences run concurrently (one per element, a hypothesis), scrolls are picked up within 24 px (a hypothesis) and fire `IsTaken`, `Hourglass` time is the world tick while waits assume 25 script ticks per second (units to be settled by an oracle trace), text dismissal has no canonical input event yet (replays do not reproduce it), stubs cover animations, doors, remarks, traps and combat-related natives. Winning shows the won debriefing parchment and returns to the menu (campaign progression to the next level is not wired); losing is not modelled (no combat).
- AI: rail programs run (6 of 19 opcodes by inference, the rest no-ops); no view cones, alarm, combat, items, quick actions.
- UI: options, profiles, load/save, movies are not implemented (credits work) (their menu entries are drawn on the
  disabled plate); the HUD is a frame only (no action icons, minimap; the money / clover values are placeholders, not campaign state); the briefing lacks the character
  picture; the pause tint is an approximation.
- Profile-index -> sprite mapping done (`profile.cpf` SD / CV / PC tables; NPCs, civilians and `TOTO` actors wear their table sprite). Open: which hero fills a `SCOT` slot (campaign state; heroes are assigned in file order), the stat fields; walk timing placeholder.
- Original path graph undecoded (we use our own grid over the boundary plus the projection areas, so the town maps are walkable); layers/sectors/doors/climbing not modelled (every area is flat).
- Save compatibility, video, Linux/macOS window testing, Android: not started.

## How to run

```
cargo run -p opensherwood-app --release -- --game-dir "<your GOG install>"        # main menu, Play! starts mission 1
cargo run -p opensherwood-app --release -- --scenario mission:EmbTut_FoC_EC --game-dir "<your GOG install>"
cargo run -p opensherwood-app --release -- --scenario map:nottingham --windowed
```

In the menu: click Play! (or use the arrows and Enter), Enter / the V seal pages through the briefing. In the
mission: left click selects, right click orders a walk (around obstacles), arrows / screen edges scroll, F11
toggles fullscreen, Escape opens the pause menu (Escape again continues; Quit asks, then returns to the menu).
`python harness/tools/play_window.py --flow menu` plays this flow with the real mouse. See `docs/build.md`.
