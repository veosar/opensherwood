# Status report, 2026-09-02 (day 1)

Written for the maintainer, who follows the project on GitHub. Everything below is on `main`.

## Honest one-line summary

The engine is not a playable game yet: it loads every retail mission's map and actors, you can select Robin
and walk him around obstacles with pathfinding, characters animate with the real sprites, music plays, but
there are no objectives, dialogues, AI, combat, HUD or menus. The format work that the whole port depends on is
largely done (see below), and the test harness plays the engine autonomously.

## What works (verified by tests and inspected captures)

| Area | State |
|---|---|
| Formats | Backgrounds, minimaps, UI archives, sprite bank (every frame), animation blocks, maps (occluders, walkable area, projection areas), missions (all chunks of all 39 files), script container, fonts. Specs in `docs/formats/`. |
| Engine core | Deterministic fixed-tick world, canonical hashing, validated snapshots, replays, walkable geometry, A* pathfinding, sprite animation state, mission spec. |
| Rendering | CPU compositor: background + sprites + foreground occlusion + bitmap-font text; winit/wgpu window, borderless fullscreen by default, F11. |
| Audio | Ogg Vorbis music per map / menu theme, PCM effects channel. |
| Scenarios | `corridor` (synthetic), `map:<name>`, `mission:<name>` (all 39 load). |
| Harness | 25 tests (synthetic on CI for Linux/Windows/macOS, data-backed locally), determinism fixture, `drive.py`, `play_window.py` (real mouse/keyboard). |
| Reviews | Two Codex adversarial reviews answered (`docs/decisions/reviews/`); a full independent review is being produced by `scripts/codex_full_review.ps1`. |

## What does not work yet

- Script VM: SCB opcode semantics unknown, so no objectives, triggers, dialogues, cutscenes, win/lose.
- AI: patrol programs are decoded but not executed; no view cones, alarm, combat, items, quick actions.
- UI: no HUD, main menu (module written, not wired), options, profiles, saves; `docs/original/ui-flow.md` from the
  black-box analysis of the original is the input for this.
- Profile-index -> sprite mapping unknown (NPCs use a default soldier sprite); walk timing placeholder.
- Original path graph undecoded (we use our own grid); layers/sectors/doors/climbing not modelled.
- Save compatibility, video, Linux/macOS window testing, Android: not started.

## How to run

```
cargo run -p opensherwood-app --release -- --scenario mission:EmbTut_FoC_EC --game-dir "<your GOG install>"
cargo run -p opensherwood-app --release -- --scenario map:nottingham --windowed
```

Left click selects, right click orders a walk (around obstacles), arrows / screen edges scroll, F11 toggles
fullscreen, Escape does nothing yet. See `docs/build.md`.
