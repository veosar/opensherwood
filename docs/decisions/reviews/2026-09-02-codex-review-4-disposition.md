# Disposition of Codex review 4 (script VM, hidden actors, resource bounds)

Review: `2026-09-02-codex-review-4.md`, verdict fix-then-merge. Rows 3, 4, 5, 9, 10 and 13 answered by the
implementer of the formats / assets / protocol / render / navigation crates; the remaining rows are the lead's.

| # | Finding | Disposition |
|---|---|---|
| 3 | Replay recorder byte accounting | **Done.** `opensherwood-protocol` gained `ReplayRecorder`: every event and checkpoint line is serialised and its bytes counted against `replay_limits::MAX_BYTES` (a reserve for the final checkpoint, sized at the highest tick, is set aside at `replay.start`) before the recorder is mutated; ordering, tick, event and checkpoint quotas are checked there too, and a refused push leaves it unchanged. `Replay::to_jsonl` is fallible (`try_reserve`, refuses above the cap). The engine's `check_recording_quota` costs each planned event at its longest representation and each planned checkpoint at the reserve size before a `step` runs; `step_recorded` marks the recording failed on the first refusal (window mode); `replay.stop` uses `finish`, which cannot exceed the cap. Tests: `recorder_accounts_every_byte_and_refuses_without_mutating`, `recorder_at_the_format_cap_with_worst_case_events_stays_parseable` (64 MiB of `pointer_move` at `i32::MIN`, ten-digit sequence numbers: the byte cap binds at about 570k events, before the 2^20 event quota, and the output parses), engine `step_refuses_to_exceed_the_recording_quotas`, `stop_never_exceeds_the_byte_cap`. |
| 4 | Content fingerprint cache | **Done (by removal of the cache).** A same-size edit with a preserved mtime is invisible to size and timestamps, and the change time (`ctime` / NTFS `ChangeTime`) is unstable in `std` on Windows (`windows_change_time`, `windows_by_handle`) while `unsafe` FFI is not allowed in the assets crate, so no metadata key can carry the "any edited byte" guarantee on the user's platform. `GameDir::fingerprint` now walks every layer's directory again on each call (added and removed files are seen) and streams every file, with a stat before and after each read (size, mtime, ctime on Unix / creation time and attributes on Windows) and up to three re-reads when they disagree, so a concurrent replacement is never hashed as a mix. Measured cost on the retail installation (1 GiB): 0.70 to 0.78 s warm (release build, single thread). The lookup index is still the one built at `open` (an added file resolves after reopening; documented). Tests: `fingerprint_sees_a_same_size_edit_with_a_preserved_mtime`, `fingerprint_sees_files_added_and_removed_after_open`, `fingerprint_fails_when_a_file_cannot_be_read` (exclusive open on Windows, mode 0 on Unix). `docs/architecture.md` updated. Open: the engine still fingerprints at every `snapshot` / `restore` / `replay.start`; binding the fingerprint to the load (`reset`) would be both cheaper and semantically tighter (a snapshot carries the identity of the content its world was built from) and is left to the lead. |
| 5 | Navigation cost bounds and restore ordering | **Done (core side within `nav.rs`; one line left for the VM agent).** `nav.rs`: `MAX_POLYGONS = 2^16`, `MAX_EDGE_TESTS = 2^26` (retail maps need at most 136k edge tests over at most 1004 polygons, measured on all nine `.rhp`), each polygon is scanned over the rows it spans only, `NavGrid::check_budget` computes the exact work without allocating, `try_build` checks it first, allocates with `try_reserve_exact` and charges every edge test to a budget (an exceeded budget is an error), and `build` degrades to a grid with no walkable cell instead of panicking. The app's `restore` runs `NavGrid::check_budget` on the snapshot's geometry before any world is touched, and the same-scenario path restores into a clone (the core's `World::restore` rebuilds the grid inside it) that replaces the session's world only afterwards; the cross-scenario path already built the temporary world first. Tests: engine `restore_refuses_geometry_over_the_navigation_budget`, nav `budgets_bound_polygons_cells_and_work`, `scans_only_the_rows_a_polygon_spans`. For the VM agent (`world.rs`): `check_geometry` should also call `NavGrid::check_budget(&geometry, map_size.0, map_size.1)` so `set_geometry` and `World::restore` refuse over-budget geometry themselves rather than getting the degraded grid, and `ensure_nav` may switch to `try_build` and surface the error. |
| 9 | Fail-open retail loading | **Done.** `load_map` fails the scenario when the map's `.rhp` is missing or malformed; `mission::load` fails when `Configuration/profile.cpf` is missing or malformed or when a sprite profile the mission references through it cannot be loaded; `load_catalog` fails when the sprite bank cannot be opened or a profile cannot be loaded. Each fallback survives only behind `OPENSHERWOOD_LENIENT_ASSETS=1` (`docs/build.md`), logged with the variable's name. Left as they were: an actor whose table index is outside the table (data inconsistency, counted as a fallback in the load summary) and a missing or untranslatable script (ADR-0008, the VM agent's). The catalog-relative validation skip on an empty catalog (`world.rs`) is moot for retail now that an empty catalog cannot come from a failed load, but the VM agent may still want to close it. |
| 10 | RGBA materialisation budgets | **Done.** `image_blob::RgbaBudget` (cumulative bytes, `charge` / `release` / `reset`) and `Image16::rgba8_len` (`width * height == pixels.len()`, checked `* 4`), `Image16::try_to_rgba8_with(budget, map)` (`try_reserve_exact`, the budget charged first and released on allocation failure), `try_to_rgba8_565`, and a fallible `to_rgba8_565`; `sprite_decode::to_rgba8_keyed` is fallible and `to_rgba8_keyed_budgeted` charges the sprite bank's budget (`sprites::CACHE_LIMIT`, 256 MiB: the cache is cleared when a frame does not fit next to it, a frame that does not fit on its own is an error).
