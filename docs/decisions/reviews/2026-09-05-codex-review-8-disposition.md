Review: `2026-09-05-codex-review-8.md` (commits `4475d16..db32208`). Verdict there: redesign, on the taint
model's closure, the callback retry semantics and the AI work budget. Answers per finding; the core items

|---|---------|-------------|
| 1 | Taint not dependency-closed: uncertain opcodes, policy natives, lenient unknown calls and unread stub effects leave `assumptions` empty | **Accepted, open (core batch).** The model becomes conservative: a mission is tainted when it executes any opcode of low-confidence meaning, any native whose row is a policy rather than an observation (98, 128, 140, 245 and the rest of the policy list), any lenient unknown call, and any effectful stub on invocation; only stubs proven presentation-only stay untainted, on a registry that names each source. Constructed branch-to-win tests per source, through snapshot / restore and replay. Until that lands, `observe.script.tainted = false` must not be read as authoritative; `docs/harness.md` says so. |
| 2 | `CampaignGraph` recorded on the discarded world | **Done (`fe5b030`).** Recorded on the successor after its install; the won-flow test asserts the successor is tainted at tick 0. Snapshot / restore and replay carry the set with the VM state (hashed). |
| 3 | `ActionChange` queue re-executes partially run handlers; a full queue drops changes | **Accepted, open (core batch).** Queued callbacks run transactionally (state rolled back on exhaustion, the entry retried whole) or the queue overflow becomes a deterministic fault; tests: increment-then-spin, native side effect then spin, restore mid-backlog, full queue. |
| 4 | AI budget does not bound `advance_state`, attack target lookup or patrol path requests | **Accepted, open (core batch).** One simulation budget across perception, transitions, targets, attacks and patrol / program planning, with persisted phase cursors; mass idle-patrol and max-attack-target tests. |
| 5 | Campaign money mission-local, replays omit the starting money, `u32` money | **Done.** `ProfileSummary.money` is an `i32` (one signed type with the scripts); a won mission writes the VM's money into the selected profile and saves it (a loss keeps the profile's, whether the original does is unobserved and noted); `reset.starting_money` is a canonical input and `ReplayHeader.starting_money` records the value used, playback resets with it (protocol 6); ADR-0004's version line corrected (the mission spec is not in the snapshot; the money is VM state, which is). Tests: reset with a starting money and replay round trip; win -> profile money -> successor seeded. |
| 6 | Native-result validation is lexical; a jump into a result reader consumes `0` | **Accepted, open (core batch).** Fuse call and result into one IR instruction (the translator emits them adjacently already) and reject any jump target that is a result reader; separate `returns_value` from corpus usage; direct-jump, divergent-predecessor and loop-entry validation tests. |
