| 4 | Per-tick work not bounded | **Done.** One budget (`vm::WORK_BUDGET_PER_TICK` = 2^22 units, `VmState::budget`) charges instruction dispatch (1), call / native argument transfers (`argc`), zone tests (edges per pair), scroll checks (1 per pair), sequence elements (1) and, through `NavGrid::find_path_with` / `smooth_with` / `line_clear_with` (`nav.rs`), every A* node expansion and line-clear cell of the walks the script issues (`World::plan_path_with`). When it is spent the tick stops deterministically: the running callback is aborted, the remaining phases of `vm_tick` are skipped until the next tick, undelivered messages are requeued ahead of new ones, a walk that cannot be planned is dropped; every stop increments `counters.budget_aborts`, nothing panics. Aggregate bounds: `MAX_STACK` (2^12) on every `argc` and on the stacks (`pop_n` can no longer resize past it), `MAX_PROGRAM_CODE` (2^22) over all classes, `MAX_POLYGON_VERTICES` (2^12) per location and `MAX_LOCATION_VERTICES` (2^20) in total, `MAX_SEQUENCE_ELEMENTS` (2^16) over all live sequences (native 31 refuses beyond it). Search structures use `try_reserve` (`NavError::Allocation`); the budget-free wrappers keep a `DEFAULT_SEARCH_WORK` cap that exceeds any accepted grid's work. Player and rail-program orders use `world::ORDER_SEARCH_WORK` per order. Tests: `work_budget_stops_the_tick_deterministically_and_resumes` (a spinning `ProcessMessage` stops the tick, the queued message, zone, sequence and victory check run one tick later, same hashes on a second run; a zero budget drops a script walk), nav `search_work_is_charged_and_bounded`. Not covered: the per-tick total of NPC rail-program orders (entities x one order budget) is the pre-existing bound. |
| 5 | Hostile snapshots neither canonical nor resumable | **Done.** `VmState::validate` refuses non-quiescent snapshots (frames, argument or parameter stacks, a collecting sequence: "vm snapshot is not quiescent"), so nothing is silently discarded; the `scheduler` hash no longer encodes frames and stacks. `counters` and `budget` are diagnostics: `#[serde(skip)]`, not hashed, documented in ADR-0008 (a restored world counts afresh; `debug.vm` reports live values). `next_text_id` and every counter saturate; a saturated text counter or a full queue drops the request and counts it (`texts_dropped`). New invariants: `next_text_id >= 1`, text ids strictly increasing and below the counter, `SeqWait::Text` ids below the counter, sequence elements / tokens name existing entities and in-range coordinates, the element table names existing entities. Tests: `program_validation_is_self_sufficient_and_snapshots_must_be_canonical`, `vm_state_survives_snapshot_restore_and_is_hashed` (counters and budget absent from the JSON). |
| 6 | `Program::validate` not self-sufficient; RNG identity unchecked | **Done.** Core validation now requires: functions in table order starting at address 0, each starting with the `Enter` of its frame sizes (and every `Enter` matching its function), jumps inside their function, `LoadParam` below `param_count`, call arity equal to the callee's `param_count`, arities within `MAX_STACK`, `functions.is_empty() == code.is_empty()`, aggregate code and vertex bounds, elements binding polygons that exist; `World::validate` requires the gameplay stream to be `(seed, 1)` and the script stream `(seed, 2)`. The translator's checks stay as earlier diagnostics. Tests: `program_validation_is_self_sufficient_and_snapshots_must_be_canonical`, `rng_streams_must_derive_from_the_world_seed`. |
| 7 | Location values and tick-rate scaling can overflow | **Done.** Locations, object / scroll elements and sequence walk / teleport coordinates are bounded to `+-2^20` (`vm::MAX_LOCATION_COORD` = `geom::MAX_COORD`); entity positions to the same range (`world::MAX_ENTITY_COORD`). Native 160 forms the differences in `i64`, squares in `u128` and rounds with an integer square root, saturating at `i32::MAX`; `World::center_camera_on` clamps in `i64`. The translator uses `checked_mul` for the script-tick denominator and refuses a zero rate (`TranslateError::TickRate`). Tests through inline JSON at the `i32` extremes and at `+-2^20`: `distance_and_camera_natives_are_total_at_the_coordinate_bounds`, `program_validation_is_self_sufficient_and_snapshots_must_be_canonical`, `camera_centring_is_total_at_extremes`, script `tick_rate_scaling_is_checked`; the core extremes tests pass under `cargo test --release` as well. |
| 10 | Activation / locking edge semantics | **Done.** Native 113 on an entity clears `World.selected` when it points at it; a right-click order requires the selected player character to be alive and active (a snapshot may still select an inactive one). Locking (native 134) halts a non-player entity's current walk (target and path cleared; its rail program stays on the same instruction and re-issues the walk when unlocked; legacy patrols pause too); player characters' orders are not touched. Documented at confidence **low** in `docs/formats/scb.md`, "Engine notes" (the original's freeze may let a walk finish); pinned by `locking_mid_walk_stops_the_ai_walk_and_completes_the_barrier` (lock at tick 30 mid-walk stops the guard, completes the barrier, unlock at tick 60 resumes the rail; a locked PC keeps its order) and `deactivation_clears_selection_and_orders_need_alive_active`. |
| 11 | Restore can succeed with a silently unusable grid | **Done.** `NavGrid::build` (the degrading constructor) is gone; `World::try_ensure_nav` is fallible (`ensure_nav` kept as a compatibility wrapper that leaves `nav` empty on failure, no empty grid); `set_geometry` and `World::restore` build the grid into a temporary and commit only afterwards (a same-geometry restore keeps the live grid); every constructor builds the grid and fails instead of handing out a world without one.
