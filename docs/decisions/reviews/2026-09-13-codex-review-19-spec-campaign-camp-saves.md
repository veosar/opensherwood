# Codex spec review 19: docs/original/spec-campaign-camp-saves.md (campaign, camp and saves), 2026-09-13

Spec reviewer role (ADR-0009), with access to `re/`. Answered in the spec's next revision. Class and source-file names quoted by the reviewer as offending passages are redacted here.

1. **Blocker — CAMP-023, A2; 0x00452F20, 0x004539F0.** The campaign file stores **previous, current, selected, blazon node**, in that order. The draft reverses the first two. In the local backup, `(FFFF, 21, FFFF, FFFF)` means current mission 21 and no previous mission. Correct the grammar, field descriptions and acceptance test.

2. **Blocker — CAMP-070; 0x0051D5D0, 0x0055C3C0, 0x0055BB30.** The character-record grammar is incomplete. The base serializer writes **four** 32-bit values: its two-field loop executes twice. There are no unexplained eight bytes. After the second signature, the record contains health, one byte, **nine** u16 values, camp slot, wide name, profile reference and present flag. The draft specifies eight u16 values. This corrected framing consumes the local 98-byte character record. Remove the instruction to manufacture an opaque base block from captured bytes or zeros.

3. **High — CAMP-241, §2.6.2; 0x00456540, 0x00452F20, 0x005280D0.** `town_node` is the node’s **four-byte level code**, not its table index or a raw node reference. The outcome routine copies the code, the serializer writes it directly, and the notification uses it to select its resource. Correct its type and reference semantics.

4. **High — CAMP-124/125/134; 0x00511340, 0x0056EA70.** Only the **additional backup block** is conditional on version greater than 38; the live campaign block is serialized unconditionally. Also, the header checker does not invariably reject bad magic: a differing version can overwrite that rejection with success. Separate observed legacy behavior from the importer’s chosen validation policy. The local version-48 saves do contain blocks beginning at offsets 16 and 2729, with level state beginning at 5442.

5. **Medium — CAMP-022/124, A3; 0x0054CC40, 0x00511340.** Retain the 32-byte mission-slot framing and four discarded bytes, but downgrade “uninitialised memory” and “whatever happened to be in a register”: the export alone does not establish that explanation. Likewise, block equality and limited differences describe these particular sampled saves, not every save. A live block can differ in any mutable campaign field.

6. **High — CAMP-047/048/312; 0x00566570, 0x0056B8D0, 0x00453CD0, 0x004574B0.** The missing deployment inputs are recoverable. The mission’s `SCOT` count supplies `team_limit`; its slot flags populate the second requirement list. That list contains **capability requirements**, not more character-profile references. Its matcher examines character capabilities and accepts certain substitutes. Read-only inspection found nonzero requirement flags in **12 of 39 mission files**, covering 16 slots. Replace “empty for every node,” settle the capability matching rules, and document missing-file/chunk behavior.

7. **High — CAMP-203/204/212, B12; 0x00452040, 0x00452090, 0x00452810, 0x00452A50, 0x00451B70.** The random-filter membership decision is visible: eligible entries are **removed** when the draw exceeds `prob`; if a pass removes everything, its incoming membership is restored. Every outer attempt starts again from the source list, while slot-state mutations can persist. The forced path also restores candidates before choosing. It cannot guarantee one mission from an empty source. Correct the reduction contract and B12; specify draws only for eligible entries.

8. **High — CAMP-211, B11; 0x00452C90.** Recency filtering does **not** remove every recent mission. It visits history from newest to oldest and stops once fewer than two candidates remain. Consequently, a recent mission can remain as the sole offer. Replace B11 with an ordering-sensitive test that preserves the final candidate.

9. **High — CAMP-260; 0x00455F00, 0x0054CBF0, 0x0054CC20.** `pending` is misidentified. In the multi-candidate case, other assault/defend candidates are discarded and their ages reset; **tactical candidates** move to the secondary list when a blazon node exists, otherwise they are discarded. Document the singleton behavior separately. This correction changes both campaign offers and the purpose of a serialized list.

10. **Medium — CAMP-060/063/064/065, B7–B10; 0x0054C800, 0x00452E70, 0x004526F0, 0x00452D20.** Preserve the eight accessibility predicates and the “played, including lost” prerequisite interpretation, but specify unsigned money comparison. Qualify the reduction guarantees: deadline and obligatory filtering require multiple candidates; obligatory means nonzero; equal location/priority candidates are diagnosed and retained. Sorting uses map name, while elimination compares location identifiers, so arbitrary synthetic inputs do not guarantee one candidate per location. Correct the unconditional claims and test preconditions.

11. **High — CAMP-202/222/230, §3.3; 0x00451A90, 0x004539F0, 0x00514730.** Rebuilding offers is not restricted to once per campaign day: resolving a defend node can rebuild them within camp. Team reset occurs on the **unselected-next-mission path**, not every transition. Preserve the unusual picked-slot expiry comparison already described in §3.4, but remove broader claims that contradict these conditions.

12. **High — CAMP-310, native 165; 0x00579210, 0x00455400.** Native 165 adds the status reference without duplication, but its subsequent writes affect the **actor**, not the saved status’s `present` field. It also sets one state value to **2**, rather than clearing two fields. Describe the actual observable deployment effect; leave unresolved actor fields explicitly unknown. Native 166’s removal and HUD refresh are supported.

13. **High — CAMP-300/301/302, messages 1000/1001; 0x0050F710, 0x00578D80, 0x0058A940.** The cited call does not establish that the camp handler finishes before production or before the first tick. The message helper constructs a script invocation and submits it through the scheduler; recover its execution ordering and the omitted call arguments. The send-action origin of 1000 remains unlocated and must remain unknown in **all** normative sections. Native 249 counts HUD-selected characters, so “selected characters” and the campaign team must not be conflated. Native 239 opens debriefing; it does not establish the send path.

14. **High — CAMP-321/322/328, B31; 0x00456A40, 0x00580D20, 0x00581020, 0x00580E80.** Victory gates output calculations for kinds 0–11, **not the entire workshop pass**. Existing-stock placement, assigned-character placement and kind-12 processing can still occur without a previous victory. Replace “nothing changes in any workshop” with tests distinguishing output generation from camp reconstruction.

15. **High — CAMP-322/326; 0x00580B70, 0x00580430.** Item placement decrements a temporary quantity; it does **not** subtract placed items from persistent `stock`. It also updates a capacity-related flag. Recounting considers active matching elements, not every matching item indiscriminately. Correct the stock lifecycle and identify when recounting occurs.

16. **High — CAMP-323/324; 0x005810C0, 0x0051D4E0, 0x0055BB00, 0x00581180, 0x00484360.** Kinds 9/10 update **each assigned character’s experience state**, not a global store; kind 9 additionally checks that character’s relevant capability. Kind 11 restores **health**, capped at 100; it is not the training workshop. Correct both the workshop descriptions and their links to saved character state.

17. **Blocker — CAMP-320–328, §9.2; 0x005806C0, 0x00581020, 0x005810C0, 0x00581180, 0x00580E80.** Production remains unimplementable: the output formula, supervisor contribution, rounding/overflow details and kind-12 behavior are missing. Natives 199/200 establish zone/capacity and work-spot registration, but that does not settle production. Supply those rules and executable acceptance expectations before clearing this scope. Also document the version-46 discarded assignment word; version 47 is not the first version containing an extra u16.

18. **Blocker — CAMP-013/101/250/251, B16–B19; 0x004E3260, 0x004A1BC0, 0x00438710.** Counters 4/5 do **not** count returning and lost campaign teammates. The bookkeeping filters soldier-family actors on the hostile side, then counts those alive and dead. Player-character actors have a different type. The 70-point bonus likewise concerns qualifying surviving hostile actors, not “special team members.” Rename the counters, correct spared-lives semantics, and replace the team-survival tests.

19. **High — CAMP-251/252; 0x0049FC80, 0x00485200, 0x0051D4E0, 0x004A5A00, 0x0047E9A0, 0x004520E0.** The 100-point event is an **experience whole-value increase**, not an inventory pickup. The 50-point path detects a hostile actor’s transition into death after damage. Also, only delta updates propagate money/score into mission statistics; direct counter setters do not. Correct the triggers and remove “every change.”

20. **High — CAMP-250/280/291; 0x004E3260, 0x00456540, 0x0055D1A0, 0x00438710.** “No counter changes at all” on loss is false: recording a loss can clear blazons, and outcome/loot processing precedes the victory branch. The recruit-count expression is absent from the export; it is not established as a simple level accessor. Difficulty is the profile’s final serialized summary word, consumed as easy/medium/hard; four records in CPF table B do not establish four difficulty presets. The sibling combat specification explicitly contradicts that interpretation.

21. **Medium — CAMP-101/270/271/272; 0x0055D370, 0x00528810, 0x00456DB0, 0x0050E800.** The campaign-map spared percentage uses unsigned integer division, but the profile updater uses floating-point conversion whose expression is absent: identical arithmetic is not proved. Progress’s ordinary division has no zero-denominator guard. Playtime accrues at save/transition checkpoints from an active interval and clears its start marker; it is not simply calculated once at level end. Add boundary and repeated-save tests.

22. **High — CAMP-263, B27, §8.6; 0x00455A70.** No clamp-to-zero is visible for an already exceeded blazon requirement; narrow unsigned comparisons matter. On a zero divisor, the routine reports and returns before dividing. Resolve the spec’s contradictory instructions to “refuse” and to continue identically, and distinguish any safer OpenSherwood behavior from the original.

23. **Medium — CAMP-290/071; 0x004524B0, 0x00455BF0, 0x0055BF00.** No recruit coin-flip draw occurs when recovery is empty. Recovery also modifies experience and clears carried-item fields; “health re-rolled” lacks evidence. Name generation contains a fixed fallback path, contradicting “keep the colliding name after ten attempts.” Specify these state changes and RNG consumption without reproducing fallback game text.

24. **High — CAMP-350/351/352; 0x005788A0, 0x004A5C30, 0x005EF320.** Native 24 codes 0/1 change the style without restoring previously overridden colours. The hostile actor also has additional colour entries beyond the claimed three-entry set. Calls to one colour-conversion helper cannot prove “No grey dot colour exists in the image” or explain every apparent grey dot. Replace that universal assertion with the limited observed evidence; state-dependent rendering remains unspecified.

25. **Blocker — expression filter; CAMP-002/325, §§0, 2, 3.11, 5; 0x00452F20, 0x0055D1A0, 0x00580350.** Offending passages include **“`signature(<class name redacted>)`”**, **“`signature(<class name redacted>)`”**, **“`<class name redacted>`”**, and **“nine individual facts, not a data table”** accompanying the ordered workshop/item mapping. These reproduce recovered identifiers and reconstruct a curated mapping; renaming it “individual facts” does not satisfy ADR-0009. Replace identifiers with independent semantic signature labels and remove the prohibited aggregate mapping pending a compliant specification treatment. The heuristic asset checker passes but does not clear these passages.

26. **Medium — expression filter; §§2.2–2.4, 2.6.5; 0x00566570, 0x0055C3C0, 0x00580970, 0x0051BA00.** Remove unnecessary recovered structure: **“244 bytes in memory,” “72 bytes in memory,” “52 bytes in memory,”** and **“first, second, fourth, third of the in-memory block.”** Specify wire layouts and required state, using file-relative field names. Also replace the recovered diagnostic term **“ARES”** with an independently chosen name unless an exact compatibility requirement is demonstrated.

27. **High — CAMP-002, §8.1; 0x005E1B70.** The signature policy contradicts itself: a warning-only mismatch cannot simultaneously establish that identical bytes are mandatory for acceptance. Remove the hard-coded/private-build-table alternatives and state the actual compatibility requirement. A cache derived from existing saves also needs a defined first-run case when those files do not yet exist.

28. **High — necessity record, identity block, acceptance and snapshot contracts; address: document-wide.** Replace **“Four years of data observation”** with supported history and retract **“Stopping condition reached”**: the draft’s own open questions include essential production, deployment and message behavior. Record stable analyst/reviewer identities, reviewer exposure, and reviewed blob `6601ef353cb680df86e7b23613627c0cd6b032d5`; keep publication approval separately pending. Label A2–A4 as observations of mutable local fixtures, not universal acceptance values. The corrected CPF grammar consumes all **30,441 bytes**, and the profile archive consumes all **430 bytes**, but those checks do not prove behavioral semantics.

29. **High — implementer handoff, §§8–10; addresses cited above.** Before handoff, provide the corrected capability requirements and spawn matching; complete reduction retries and secondary-list behavior; production arithmetic and assignment lifecycle; camp selection/departure and native-173 state transitions; message delivery ordering; recruitment and statistics formulas; persistent-character initialization; save failure/version behavior; and state-dependent HUD/minimap rules. Reconcile four named RNG streams with the snapshot’s “five,” and specify reconstruction of excluded work-spot state. The current `engine.rs` successor heuristic does need replacement, but this draft is not yet a sufficient replacement contract.
