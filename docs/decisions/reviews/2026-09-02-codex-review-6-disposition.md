| 2 | The VM does not have one work budget per tick | **Done (core, ruleset 7).** `VmState::budget` is granted in exactly two places: `World::vm_tick` grants `WORK_BUDGET_PER_TICK` (2^22) at the start of every world tick, and `attach_script` grants `WORK_BUDGET_AT_LOAD` (its own constant, 2^22) once for the load-time run (`Initialize` on every class, `PostInitialize`, the first sequence elements); `vm_grant_budget` has no other caller. `vm_event` (the `IsTaken` / `ReachPoint` / `ActivatedBy*` / `ActionChange` hooks, hence the scroll pickups of `vm_scrolls`) and `vm_dismiss_text` reset nothing: they draw from what the tick (or the load run) left. A dismissal after an exhausted tick removes the page and the sequence behind it continues at the next tick (documented in ADR-0008, `vm.rs` and `docs/formats/scb.md`; a fixed between-ticks allowance was rejected because it would be a second budget per tick). Tests: `simultaneous_is_taken_callbacks_share_one_tick_budget` (three spinning `IsTaken` handlers approached at once: one runs per tick, instructions per tick <= 2^22, a hook called at zero budget returns `None` and refills nothing, the remaining scrolls fire on the following ticks), `dismissals_between_ticks_draw_from_the_ticks_remaining_budget` (a native-202 notice dismissed after load keeps the load remainder; a native-203 page dismissed after a spinning tick leaves the budget at 0 and the camera move behind it waits for the next tick). The scan phases also charge one unit per entity looked at (`vm_zones`, `vm_scrolls`), so the classes x entities loops are bounded too. ADR-0004 versions line and ADR-0008 budget bullet updated. |
| 3 | The budget omits the dominant hostile-input costs | **Done (core).** Native 97 charges one unit per polygon edge and native 204 one unit per entity looked at plus the edges of every player character tested, both before scanning and on a polygon borrowed from the program (`polygon_in`; the cloning `polygon_of` is gone); an unaffordable scan stores nothing, returns 0, zeroes the budget and the callback aborts at its next instruction. Navigation (`nav.rs`): a search charges its initialisation before the three arrays are allocated, one unit per `INIT_CELLS_PER_UNIT` (64) cells (a fixed per-cell cost next to an expansion's eight neighbour tests and heap operation: 65,536 units on a `MAX_CELLS` grid, about 2,000 on a retail map), then one unit per expansion, one per unwound path cell (before the fallible push) and one per smoothed output point; `World::plan_path_with` charges the conversion of the final path (one unit per point plus the target) and reserves it fallibly before producing any point. Tests: nav `a_search_without_budget_charges_initialisation_before_allocating` (a 2048 x 2048-cell grid, the largest accepted: budgets 0, 1, init - 1 and init are `WorkExhausted` before any search array exists, init + 1 starts and stops at the first expansion; on the small grid the unwinding is measurable and smoothing succeeds at exactly its cost and fails one unit short), world `plan_path_charges_its_conversion_and_needs_exactly_its_work` (exactly the measured work plans the same path, one unit less clears the order, zero allocates nothing), vm `polygon_natives_charge_edges_and_entities_before_scanning` (a `MAX_POLYGON_VERTICES` polygon: the tick charges exactly 15 + 4096 + (4 + 4096) units for the two natives; a budget of 4096 aborts before native 97 scans, one covering 97 but not 204's first entity aborts there, the VM is quiescent after both). Not charged: `nearest_walkable` (a bounded 17 x 17 spiral per order). |
| 4 | Valid programs can leave non-quiescent VM state | **Done (core).** `vm_invoke` wraps `vm_run` and every exit (return, budget abort, fault, frame push failure, trap) passes through the one `teardown` (frames, argument stack, parameter stack, `collecting`); the per-arm clears are gone. `Program::validate` adds `check_stack_balance` per function: a worklist walk assigns every reachable instruction the parameter / argument depths, a `Call` / `Native` needs at least its `argc` values pushed, a `Return` (or falling off the end of the function) needs both stacks empty, join points must agree, depths stay within `MAX_STACK`; unreachable code is not walked. All 39 retail programs pass it (`harness/tests/data` green). Tests: `every_callback_exit_tears_down_to_a_quiescent_vm`: (a) budget abort with values on both stacks, (b) trap with two surplus arguments and a sequence being collected, (c) a nested return while the caller holds values on both stacks, each followed by `World::validate` and a JSON snapshot restored into a fresh world with equal hashes; (d) a program returning with surplus values and one calling with too few pushes are refused ("stacks are not balanced at instruction"), and the former, injected past validation, still returns to a quiescent VM. With the balance check a *valid* program cannot reach its outermost return with surplus values, so (c) and (d) are the return-path coverage; the earlier snapshot test (`program_validation_is_self_sufficient_and_snapshots_must_be_canonical`) keeps refusing injected non-quiescent state. |
