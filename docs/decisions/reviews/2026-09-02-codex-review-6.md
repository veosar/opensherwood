# Codex adversarial review 6: commit d5d7cec (2026-09-02)

Disposition in `2026-09-02-codex-review-6-disposition.md`.

Reviewed the `d5d7cec` commit object; `HEAD` advanced to `4deba8b` during the audit, so all line numbers below refer to `d5d7cec`.

## Findings

1. **Critical — The clean-room sweep committed data-derived artifacts.**  
   `harness/harness/out/replays/h01_from_first_page.jsonl:1-30` contains a retail-content fingerprint and hashes from a real mission run. It is generated by `harness/tests/data/test_script.py:159-176`, which starts `Engine` without an artifact directory and writes a relative replay path; when pytest runs from `harness/`, the default `./harness/out` becomes the unignored nested path. This violates `docs/harness.md:127-130` and AGENTS.md’s prohibition on uploading data-derived artifacts. The new `EXPECTED_AT_LOAD` table at `test_script.py:18-63` is also an exact, generated catalog of all mission names and per-mission runtime results. `check_no_assets.py` nevertheless passes.

   Concrete fix: remove the replay from the commit and make a maintainer decision about removing it from already-pushed history; pass an explicit ignored artifact directory or `tmp_path` to every data-backed `Engine`; reject nested `harness/out` paths and retail replay JSON in `check_no_assets.py`; replace the exact mission table with relational assertions or an untracked local golden.

2. **High — The VM does not have one work budget per tick.**  
   `vm_tick` resets the budget at `crates/opensherwood-core/src/vm.rs:1665-1669`, but every `vm_event` resets it again at `vm.rs:1635-1637`. `vm_scrolls` calls `vm_is_taken` through that path at `vm.rs:1842-1860`, so each nearby scroll can grant a fresh \(2^{22}\)-unit budget during the same tick. `vm_dismiss_text` also resets at `vm.rs:1571-1580`; the non-modal path invokes it immediately after the world step at `crates/opensherwood-app/src/engine.rs:394-425`, granting another budget in that session tick. The test at `vm.rs:3258-3403` covers a spinning message but neither reset path.

   Concrete fix: create one explicit budget scope at the start of a scheduler/session tick and pass it through callbacks, events, dismissals, sequences, and pathfinding. Load-time execution can have a separately named budget. Add tests with several simultaneous `IsTaken` callbacks and a native-202 notice after earlier tick work.

3. **High — The budget omits the dominant hostile-input costs.**  
   Instruction dispatch charges only `1 + argc` at `vm.rs:2060-2065`. Native 97 clones and scans a polygon (`natives.rs:286-295,536-543`); native 204 scans up to 65,536 entities against that polygon (`natives.rs:421-438`); these costs are uncharged. Navigation allocates and fills three arrays for up to four million cells before its first budget check (`nav.rs:323-355`), then leaves path unwinding and final conversion uncharged (`nav.rs:339-349`, `world.rs:673-679`). A call reaching pathfinding with zero remaining budget can therefore still perform large allocations.

   Concrete fix: charge native-specific cardinality costs before cloning or mutation, borrow polygons instead of cloning, charge entity×edge tests, and charge navigation initialization, unwinding, smoothing output, and conversion. Use fallible allocation for the final path and add zero/tiny-budget tests at maximum accepted sizes.

4. **High — Valid programs can leave non-quiescent VM state that the engine itself cannot restore.**  
   Validation rejects non-empty stacks at `vm.rs:1081-1091`, but budget abort and unknown-native trap clear only frames and collection state (`vm.rs:2065-2069,2140-2145`). Normal return also leaves surplus argument or parameter values (`vm.rs:2081-2085`); `PushArg` is permitted at `vm.rs:2126-2131`, and program validation performs no stack-balance analysis. Consequently, a valid callback can push and return, spin until exhaustion, or trap with residual stack entries. `World::snapshot` serializes that state without validation (`world.rs:1274-1285`), while restore subsequently refuses it. The test at `vm.rs:3407-3543` only injects malformed snapshot state; it does not make the VM produce it.

   Concrete fix: use one callback teardown path that clears frames, both stacks, and collection state on every exit. Add successful-return, budget-abort, and trap tests with pending stack values, followed by `World::validate` and JSON snapshot/restore.

5. **High — Replay and restore omit authoritative presentation state; native-202 notices retain prior-session history.**  
   RPC stepping, window ticks, and playback do converge on `Session::advance` (`engine.rs:502,1132-1133,1288,1593`), so the session-tick unification itself is real. However, checkpoints contain only the world tick and world hashes (`engine.rs:837-868`). `install` resets the screen and elapsed tick but never clears `notice`, despite claiming presentation state comes from the new world (`engine.rs:1102-1128`). That notice is rendered at `engine.rs:1177-1181` but hidden from `ui_state` while on the world screen (`engine.rs:630-632`). Thus `replay.play`, which resets at `engine.rs:1559`, can inherit an old overlay and still report every checkpoint matching. Same-scenario restore replaces only `World` at `engine.rs:1381-1402`, preserving a later notice TTL and session tick; a snapshot taken while a notice is visible cannot reproduce the framebuffer suffix.

   The data replay test (`harness/tests/data/test_script.py:154-206`) checks world hashes, tick lag, and only the final UI state. Its restore test (`:209-234`) compares only world hashes. Neither proves screen, notice, or framebuffer reproduction.

   Concrete fix: clear every per-world presentation field during installation; add a session checkpoint digest covering screen state and notice text/TTL; either snapshot/restore the relevant session state or refuse snapshots while such presentation state exists. Compare UI and selected framebuffer hashes on every replay/restore session tick.

6. **High — A replay with no checkpoint can report successful playback.**  
   `Replay::from_jsonl` accepts an empty checkpoint list at `crates/opensherwood-protocol/src/lib.rs:511-580`; its own round-trip test explicitly constructs one at `lib.rs:918-930`. Playback initializes `first_divergence = None` and succeeds without comparing anything at `engine.rs:1575-1621`. This directly contradicts ADR-0004’s statement at `docs/decisions/ADR-0004-protocol.md:60-62` that tick 0 is compared so a replay reproducing nothing cannot report no divergence. `test_replay.py:85-95` corrupts an existing tick-0 checkpoint but never deletes it.

   Concrete fix: require the first checkpoint at tick 0 and a terminal checkpoint at `last_tick`; reject missing/all-deleted checkpoints before reset. Add tests deleting tick 0, deleting every checkpoint, and deleting the final checkpoint.

7. **High — Strict mission loading still accepts unbindable scripts.**  
   `bind_class` records unresolved bindings in `TranslateReport.unbound_classes` (`opensherwood-script/src/lib.rs:251-270`). `translate_script` merely copies that list into statistics and attaches the program (`opensherwood-app/src/mission.rs:505-522`), while `build_spec_checked` rejects only `script_error` (`mission.rs:337-355`). This contradicts disposition row 8’s claim that an “unbindable script” fails strict loading. The all-missions test also accepts any exception for its two expected failures (`test_script.py:247-252`), so it does not prove the documented failure reason.

   Concrete fix: reject non-empty unresolved bindings in strict mode, or explicitly classify legitimate helper classes separately. Return a structured error and assert that exact error in the data test.

8. **Low — A public navigation API remains fail-open.**  
   `World::ensure_nav` silently discards `try_ensure_nav` failures at `world.rs:626-630`. There are no production callers in `d5d7cec`, so restore and `debug.nav` are fixed, but this remains an easy path back to a world with no navigation grid.

   Concrete fix: remove or privatize the wrapper and require callers to handle `Result`.

9. **Medium — The disposition and status report are not auditable or internally accurate.**  
   The referenced `docs/decisions/reviews/2026-09-02-codex-review-5.md` does not exist in `d5d7cec` or its reachable history, although the disposition references it at line 3 and status references it at `docs/status/2026-09-02.md:30`. Status says all 39 missions load at line 28, then says strict mode refuses two at line 34. It reports 25 synthetic and 23 data tests at line 29; `d5d7cec` contains 21 and 27 test functions respectively, with no parametrization. Lines 25 and 30 also repeat the disproved “validated snapshots” and “one work budget per tick” claims.

   Concrete fix: restore the source review, correct strict/lenient scenario wording and test counts, and mark budget, snapshot, replay-screen, and clean-room rows open until regression tests cover them.
