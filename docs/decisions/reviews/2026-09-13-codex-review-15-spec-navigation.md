# Codex spec review 15: docs/original/spec-navigation.md (navigation), 2026-09-13

Spec reviewer role (ADR-0009), with access to `re/`. Answered in the spec's next revision. Class and source-file names quoted by the reviewer as offending passages are redacted here.

1. **Blocker — NAV-024, NAV-120, NAV-130, NAV-141, NAV-142; §6.7 — expression filter fails.** Addresses: `0x004f9d60`, `0x00556490`, `0x005532a0`, `0x004d7880`. Offending passages include “`A.parent = e`, `A.g = g'`”, “set parent, `g`, side”, “per-node search state at run time (g, h, f, parent edge, open flag, chosen bits)”, “sets the worker's thread priority”, and “slot at offset 0x170 of the player-character class”. These prescribe recovered bookkeeping, branch structure, or internal layout. Also justify or remove “element ids are the program's own order types” and “the console's ‘EULER’ graph”: neither is covered by the stated file-token exemption. Replace these passages with required outcomes and observable ordering constraints. The automated asset check passes; its result does not clear these expression violations.

2. **High — §2.3 Edge layout, NAV-024, NAV-046 — the second edge word is not an always-zero float.** Addresses: `0x00558670`, `0x00555a10`. It is consumed as a **32-bit mask** controlling edge availability. Nonzero values occur on Croisement01/02/03, Nottingham, and York. For example, Croisement01 edge 12 has integer value 512; interpreting its bits as a float produces a tiny nonzero value. Correct both the field type and the claim “0.0 on every retail edge”.

3. **Blocker — §2.2 obstacle field, NAV-012, NAV-024, NAV-046 — dynamic navigation is missing.** Addresses: `0x004eb120`, `0x00555a10`, `0x005559b0`, `0x00556470`, `0x004d28e0`. The obstacle word labelled “unknown_id (0)” is nonzero on those same five maps. Obstacle, node, and edge masks determine availability under the sector’s current state. Patches change that state and update navigation geometry. Normal level initialization establishes `0x55555555`, not the loader’s temporary zero. Specify initialization, patch transitions, affected paths, and save/restore behavior before clearing navigation.

4. **High — NAV-020 and §2.3 — graph regions cannot be identified unconditionally with polygon positions.** Address: `0x00558670`; nine-map probe. Four sectors violate `region_count = 1 + obstacle_count`: Croisement03 `(layer 0, sector position 0)` has 22 versus 23; Nottingham `(0,0)` has 12 versus 13 and `(2,7)` has 5 versus 6; York `(0,0)` has 22 versus 23. Preserve the independently encoded graph hierarchy. The assertion that unmatched nodes were “displaced by the editor” is unsupported and must become an inference or unknown.

5. **High — §2.3 Node vectors — the stated relationship to file vertex order is false.** Addresses: `0x00558670`, `0x00553a10`. On Lincoln, only 149 of 633 nodes match each stated vector formula against the corresponding polygon’s serialized order. Reversed orientation occurs, and other maps have additional mismatches. Specify the vectors as stored geometric inputs and establish their orientation for the wedge tests; an implementer must not regenerate them from the current prose.

6. **Medium — §8 — replace the inaccurate validation record with reproducible byte checks.** Addresses: `0x00558670`, `0x0051b2a0`. I independently decoded and re-encoded every `STAT` byte on all nine maps, with identical bytes and zero remainder. For two explicitly audited maps, offsets relative to the body after the version are:

   | Boundary | Croisement01 | Lincoln |
   |---|---:|---:|
   | Graph header | 2122 | 6770 |
   | First node, half-open span | 2140–2171 | 6788–6809 |
   | Edge-count word | 13607 | 26309 |
   | First edge, half-open span | 13609–13637 | 26311–26339 |
   | Record-count word | 87473 | 109135 |
   | First record, half-open span | 87475–87483 | 109137–109145 |
   | End of body | 108915 | 133005 |

   The first edge’s cost occupies relative bytes 16–19; its mask occupies 20–23. Costs differ from corner distance by at most approximately 1.414 pixels across the nine maps. Also correct “single bits on forest maps”: combined masks occur, and Nottingham/York have nonzero node masks. All 140 passage approach points are inside their respective sectors; 138 and 133 count only points exclusively inside that side. “Inside neither” does not prove boundary coincidence.

7. **High — native 4, §7.9 — lift doors are included.** Addresses: `0x005716a0`, `0x0057e060`, particularly `0x0057e14c` and `0x0057e342`. The lift loader appends its doors to the same flat list queried by native 4. On all nine maps, `FARM` precedes ` AZ `, so lift doors follow the `FARM` doors. Lincoln therefore has 79 entries after both chunks, not 59. Remove “lift doors are **not** in it”.

8. **High — NAV-170 — the door admission table conflates distinct door types.** Address: `0x0051abe0`. Type 0 does not perform the building-capacity test assigned to it. Types 1 and 2 perform entry-side capacity checks, but type 2 rejects the plain soldier subclass that type 1 can admit. The gate/default handling distinguishes civilian locks from soldier locks; “other classes: lock_soldier clear” is too broad. Recheck each supported actor category and crossing direction and replace the incorrect rows with behavioral requirements.

9. **High — NAV-192, NAV-200 — ladder admission is reversed.** Address: `0x0057de30`. For kind/type 2, the routine rejects the plain soldier subclass and accepts other members of the relevant human family, including player characters. It does not mean “only soldier-class characters of the plain subclass”. This routine describes lift admission; treating it as a generic building-kind rule also needs correction.

10. **Medium — natives 182, 186–189, 191 — specify adapter semantics and failure cases.** Addresses: `0x00406810`, `0x004068d0`, `0x00406900`, `0x00406930`, `0x00406960`, `0x004069c0`. The adapters normalize setter arguments to boolean values and return zero. Thus “lock_pc = v” is wrong for arbitrary script integers. Native 182 zero-extends the stored byte. The lock-byte ordering and unlock-also-opens behavior are otherwise supported. Native 191 checks the door handle but does not check whether its leaf exists; empty leaf polygons are discarded by `0x0051b2a0`. Record that unsupported-input behavior separately from an OpenSherwood safety decision.

11. **High — NAV-100 — alternate click resolution selects the second occupied layer.** Addresses: `0x004e9760`, `0x004e9920`, `0x004debf0`. The ordinary resolver already stops on a blocked layer. The alternate resolver remembers the first nonempty result and returns the **second nonempty result**, falling back to the first if none follows. “First layer … instead of skipping blocked layers” is incorrect. Also, patch/lift/leaf hits share one traversal; they are not three globally ordered categories. Clarify the distinction between this traversal order and the misleading priority summary in §7.5.

12. **High — NAV-110, NAV-111, NAV-140 — free-ground testing and unsticking are misdescribed.** Addresses: `0x004f5750`, `0x004ed070`, `0x004ecf60`, `0x00467a50`. The tested input is a **box**, checked against enabled wall segments, including sector-boundary segments. It is not a point-in-obstacle-polygon test. The walk-order correction expands the existing character box by **0.5 pixels per side**, not a box of ±25 pixels. Correct the constants table and distinguish box clearance from sector membership.

13. **High — NAV-141 steps 1–2, NAV-142 — the unstuck flag has the wrong provenance.** Addresses: `0x00552e00`, `0x005547c0`, `0x004d23d0`. Request submission performs another clearance/unsticking check and sets or clears the request flag there. The flag is not simply inherited from NAV-140’s earlier correction. This affects the direct-path shortcut and whether the returned first waypoint is skipped.

14. **High — NAV-141 — reconstruction and smoothing remain underspecified.** Addresses: `0x00554b80`, `0x005553d0`, `0x005547c0`. “Direction with the fewer steps” does not settle equal-length choices or multiple compatible candidate pairs. Those choices affect returned waypoints. Smoothing also adjusts its test endpoints using a `0.00005`-scaled displacement before the corridor check; it does not test the exact endpoints stated in step 5. Supply behavioral boundary cases and expected waypoint sequences, without translating the routines’ branch structure.

15. **Medium — NAV-120 — route-search details are inaccurate.** Addresses: `0x004f9a80`, `0x004f9d60`. The reconstruction limit is not 100 doors: the initial destination plus 101 predecessor traversals can produce 102 doors before the next traversal fails. The search also excludes certain links between doors sharing the corresponding opposite-side sector, beyond merely excluding the parent link. Its heuristic is retained after first discovery rather than recomputed on every improvement. Correct these observable cases before describing the search as ordinary A*.

16. **Medium — NAV-060 — invalid sector conversion does not return “no path”.** Addresses: `0x00559660`, `0x005547c0`. The conversion reports an error and returns a value whose low 16 bits are zero; the caller subsequently uses that sector position if execution continues. Separate this original failure behavior from any deliberate checked rejection in OpenSherwood.

17. **High — NAV-150 — gait and animation playback mode are confused.** Addresses: `0x005b86b0`, `0x00464b20`, `0x005b7820`, `0x005bdc20`. Animation selection and playback mode are separate inputs. The special turning multiplier and collision bypass test playback modes, not the gait identifiers asserted here. Advance is a signed 16-bit value applied at particular animation-frame transitions; held frames contribute zero, and mode 3 has additional advancement behavior. Specify frame timing, mode mapping, and the source of the caller’s scalar before claiming an exact movement-speed rule.

18. **High — NAV-152 — arrival uses the wrong distance and describes the wrong operation.** Addresses: `0x00467a50`, `0x005fc700`, `0x00560460`, `0x005b86b0`. The type-2 approach check uses maximum-axis distance: `max(|dx|, |dy|) < tolerance + 5`. It is a separate completion check, not the general move-action arrival rule. Move actions have progress, targeting, and snapping conditions of their own. The three constructors named in §6.3 do not establish those execution semantics.

19. **High — NAV-151 — the collision threshold is not distance below five pixels.** Addresses: `0x005613be`–`0x0056140b`, `0x005fc660`. The examined character branch tests the displacement’s **dot product with movement direction**, accepting the candidate at a value of at least 5 after additional eligibility checks. It does not trigger for every nearby overlapping character. Correct the threshold, actor exclusions, and callback conditions.

20. **High — NAV-190–193 — building initialization and occupancy are incomplete or misattributed.** Addresses: `0x004c1f90`, `0x0057e680`, `0x0057e4d0`, `0x005781f0`, `0x0057ebd0`, `0x0057ec80`. The mission loader reads occupant references and a trailing byte; it does not establish the asserted building-kind/capacity layout. The constructor initializes capacity to 65535. Initial occupant placement uses `layer_count - 1`, while native 156 uses `layer_count`; specify this additional distinction. Entry and exit recursively process a player’s carried actor, which the draft omits. Also correct §7.9: native 98 with none tests **inside a building**, not outdoors.

21. **High — NAV-142; missing execution, acceptance-test, and implementation-choice sections — insufficient implementation contract.** Addresses: `0x005532a0`, `0x004d23d0`, `0x0055aa60`, `0x00561040`, lift handlers `0x0046a900`/`0x00469770`/`0x0046a000`. An implementer still lacks deterministic request scheduling and snapshot rules, precise geometric boundary predicates, complete waypoint arrival, collision/sliding behavior, lift transition timing, patch effects, door interaction, and defined invalid-input handling. There are no synthetic inputs with expected results. Add these, plus clock conversion, numeric precision, RNG ordering, and explicitly approved deviations; copying asynchronous worker timing would conflict with the repository’s determinism contract.

22. **Medium — §7 and earlier format specification — establish explicit precedence.** Addresses: `0x004ef340`, `0x00558670`, `0x00579810`, `0x005787f0`. The comparison with `nav.rs` and `geom.rs` correctly identifies the current flat grid, erosion, and merged walkable areas. However, the earlier spec still presents incompatible material-list, bond-routing, and door-native interpretations. State exactly which claims are superseded. Independent nine-map checks support the proposed `WOAW`, `TEXT`, `007 `, `FARM`, and ` AZ ` framing and their checked references; they do not clear the behavioral errors above.
